# v3 기능 Parity 기준선

작성일: 2026-05-13
기준 브랜치:
- v2 기준: `origin/master` / `v2.4.2`
- v3 기준: `origin/v3.0-dev` / `v3.5.0`
- 본 기준선 릴리스: `v3.5.1`

## 목적

PyWebView + React/Vite 구조로 전환한 v3 라인에서 v2 기능이 누락되거나 축소된 항목을 고정한다. 이 문서는 이후 패치 릴리스에서 기능을 하나씩 복원할 때 회귀 방지 체크리스트로 사용한다.

## 우선순위

- P1: 운영 핵심 기능 또는 릴리스 품질에 직접 영향
- P2: 자주 쓰는 운영 흐름의 기능 축소
- P3: 정확도, 편의성, 표현 품질 개선

## 단계별 진행 순서

1. 기준선 고정: 이 문서와 README/CHANGELOG에 누락 항목을 기록한다.
2. 공통 기반/빌드 리스크: 의존성, PyInstaller, kubectl 파싱, 빌드 안정성을 정리한다. `v3.5.2`에서 완료.
3. 대시보드 parity: 노드별 CPU/MEM 퍼센트를 복원한다. `v3.5.3`에서 완료.
4. 워크로드/파드 상세 parity: 큰 로그뷰어 이동과 파드 exec 버튼을 복원한다. `v3.5.4`에서 완료.
5. 로그뷰어 parity: 워크로드 선택과 ingress 통합 로그를 복원한다. `v3.5.5`에서 완료.
6. 토폴로지 parity: 간격 조정과 Job/CronJob 관계를 복원한다. `v3.5.6`에서 완료.
7. 보고서 parity: v2 수준의 DOCX 보고서 구조와 진단 품질을 복원한다. `v3.5.7`에서 완료.
8. 잔여 회귀 안정화: ArgoCD multi-source, k9s, 이벤트 필터 등 잔여 항목을 닫는다. `v3.5.9`에서 완료.

## v3.5.1 범위

v3.5.1은 기능 복원 구현이 아니라 parity 기준선을 고정하는 릴리스다. 실제 기능 변경은 2단계부터 패치 단위로 진행한다.
